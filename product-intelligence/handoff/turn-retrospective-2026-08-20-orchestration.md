# 本轮复盘：数字人混合执行编排

## 目标

根据用户澄清，重新界定 New API、通用云模型与 Duix/OpenTalking 本地/自托管数字人视频的边界，并把轻语 IP 全能力设为功能等价目标。

## 实际修改

- 将“全产品纯云/所有模型混合”校正为“通用 AI 云优先，数字人视频允许本地、自托管或云 API 执行”。
- 更新 OpenTalking 事实边界：最新版官方能力同时包含实时会话、视频创建和视频克隆。
- 确认自有编排与 Capability Gateway；New API 只承担标准云模型渠道。
- 确认活动/项目主线、管理端边界及轻语全能力分阶段功能等价目标。
- 新增数字人视频编排层规格，覆盖统一合同、状态机、Worker 协议、路由、回退、幂等、账本和双引擎基准。
- 用户选择方案 A；D-010 已锁定为 Duix 主生产、OpenTalking 同期合同级技术验证并在通过后作为第二引擎。

## 验证

- Deep 报告校验通过：22 个报告内独立来源 URL、19 个域。
- 工作区校验通过：24 个证据组、10 个决策、37 个需求、9 个假设。
- 现有产品代码仍未修改；研究工作流保留在 S4 决策门。

## 遗留风险

- Duix 与 OpenTalking 的主备/场景分工仍需同一组样片和任务指标验证。
- OpenTalking 是框架，不应未经部署、后端、成本和 SLA 验证就视为现成商业 API。
- 轻语全能力范围很大，必须按真实链路分阶段验收，避免静态页面再次被误判为完成。

## 可复用经验

- 混合执行应按能力限制范围，不能默认所有模型都做云/本地双路径。
- 业务工作流、能力合同和 Provider Job 三层分离，才能安全切换引擎而不污染业务对象。
