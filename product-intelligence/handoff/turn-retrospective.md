# 本轮复盘（2026-08-20）

## 目标

核查营销获客智能体 7.0、亿万流量智能体、轻语 IP 的功能模块和交互逻辑，结合当前 ip-ai，定义生产级超级 IP 营销 SaaS、管理端以及云端 API/本地模型统一接入边界。

## 实际修改

- 只读分析三款本地竞品资源并核验公开版本，没有执行竞品内命令或发布自动化。
- 审查当前 ip-ai 的前后端与 Duix 编排基础，记录真实闭环和演示页面之间的差距。
- 建立证据、主张、反证、假设、决策和需求账本。
- 形成完整产品蓝图、一页决策摘要、竞品走查、新 API 边界和可独立打开的 HTML 报告。
- 未修改现有产品业务代码，等待 S4 架构决策确认后进入产品定义和实现。

## 验证结果

- Deep 报告校验通过：20 个报告内独立来源 URL、18 个域，最大单域占比 15%。
- 研究工作区结构校验通过：22 个证据组、25 个主张、4 个反证、7 个决策、24 个需求、6 个假设。
- S3 综合质量门已通过，工作流推进至 S4 决策门。

## 遗留风险

- 活动优先是否优于工具优先仍需 8–12 名目标用户做原型对照。
- Duix 的可发布质量、失败率和人工介入时间需用 10 个真实项目验证。
- 公开用户评价样本不足，不能据此确定定价、付费意愿或留存。
- 本地节点、账本和平台发布均具有较高工程/运营风险，应按 Phase 1–3 分段交付。

## 可复用经验

- 竞品最值得复用的是可恢复工作流、统一任务与账本、素材/授权复用，不是功能数量。
- New API 适合作为通用模型渠道层，自有 Capability Gateway 才能保持业务独立和云/本地可替换。
- “快速成片”可作为轻入口，但后台仍需建立最小 Campaign/Project，避免资产与任务失去归属。
