# 超级 IP 营销 SaaS：一页决策摘要

截至：2026-08-20｜范围：中国市场｜状态：S4 决策中

## 一句话结论

不要继续给当前六个演示模块逐页“补功能”，也不要复制一个 30+ 智能体商店。应重构为“营销活动驱动的内容生产操作系统”：以 `工作空间 → IP → 营销活动 → 内容项目 → 工作流 → 产物版本 → 发布 → 效果` 为业务主链。轻语 IP 的全能力作为功能等价目标；通用 AI 默认走云 API，数字人视频可由 Duix/OpenTalking 的本地、自托管或云 API Worker 执行；自有编排层统一屏蔽执行位置。

## 三个竞品真正值得学什么

| 产品 | 应学习 | 不应照搬 |
|---|---|---|
| 营销获客 7.0 | 8 步制作向导、步骤完成条件、草稿和长任务恢复 | 只围绕单条视频、桌面壳高权限发布方式 |
| 亿万流量 | 云 SaaS＋本地桥、智能体入口、任务/积分/退款、代理与管理后台 | 功能超市、智能体堆叠 |
| 轻语 IP | IP 大脑、自动/手动双模式、本地/云端选择、素材语义匹配、批量任务 | 重本地包、浏览器自动化、把“10 秒/无限”当生产承诺 |

## 用户端建议

1. 今日工作台：待办、异常、待审核、活动进度，不是虚构数据大屏。
2. IP 大脑：人设、受众、Offer、证据、语气、禁区和平台策略，全部版本化。
3. 营销活动：目标、渠道、内容节奏、KPI 和预算。
4. 内容工作室：想法/对标/产品/已有文案四类起点。
5. 数字人工作室：脚本→配音→Duix/OpenTalking→字幕/BGM/封面→审片。
6. 资产中心：数字人、声音、素材、脚本、模板和作品版本。
7. 任务中心：进度、步骤、成本、重试、取消、人工介入。
8. 发布与复盘：平台适配、授权、审核、发布记录和效果回流。

## 管理端建议

首批必须有：租户/用户/RBAC、套餐/额度/不可变账本、Provider 通道、模型映射、路由策略、数字人/媒体 Worker、任务运维、成本毛利、授权合规、审计、Prompt/模板版本和功能开关。客服、代理/OEM、公告和完整运营分析放后续。

## New API 的位置

```text
业务 API / 工作流编排（业务事实来源）
                ↓
       Capability Gateway（自有）
       ├─ New API → 通用云模型 API
       ├─ Avatar/Media Job Router
       │    ├─ Duix 本地/自托管 Worker 或云 API
       │    └─ OpenTalking 自托管 Worker 或远程推理
       └─ 视频包装 / 发布平台专用 Adapter
```

业务层只调用 `text.generate`、`speech.synthesize`、`avatar.render`、`avatar.video_clone` 等能力名。数字人路由根据素材类型、租户策略、授权、质量、成本、时延、Worker 健康和回退链决定 Duix/OpenTalking 及执行位置；用户流程不随引擎变化。

## 90 天建议

- Phase 1：租户/权限、IP/活动/项目对象、Duix 可发布闭环、任务/账本/授权、最小管理端。
- Phase 2：Capability Gateway、New API 通道、OpenTalking Spike、数字人 Worker 协议、双引擎路由和成本仪表。
- Phase 3：补齐轻语等价能力：素材语义库、声音/数字人中心、智能剪辑、批量生产、账号发布、数据导出与效果回流。

## 现在需要确认

已确认：活动/项目优先＋快速成片；自有编排与 Capability Gateway；独立管理端边界；通用 AI 云优先、数字人视频混合执行；轻语全能力功能等价目标。

已确认双引擎顺序：Duix 主生产，OpenTalking 同期做合同级技术验证，通过后作为第二引擎。

仍需确认：首版是否接受抖音官方 API、其他平台导出包/调起发布的受控策略。
