超级 IP 营销智能体产品蓝图

三款竞品 × 管理端 × New API × 数字人混合执行编排｜研究截至 2026-08-20｜中国市场｜Deep 模式｜v0.2
推荐：把 ip-ai 重构为“营销活动驱动的内容生产操作系统”。

当前问题不是页面数量不足，而是 IP、脚本、数字人、任务、费用和发布互不认识。轻语 IP 全能力作为功能等价目标；通用 AI 默认走云 API，数字人视频允许 Duix/OpenTalking 通过本地、自托管或云 API Worker 执行。New API 承接通用云模型渠道，自有编排层统一任务、素材、路由、进度、失败恢复、成本和产物。

阶段与质量门　已完成竞品、当前源码、New API、Duix/OpenTalking、发布平台和合规研究。当前处于 S4 决策门；活动/项目主线、管理端、编排层、数字人混合执行、轻语全能力等价目标以及双引擎顺序已确认，仅首版发布边界待确认。尚未开始大规模改代码。

1. 一句话诊断

现有 ip-ai 更像“六个 AI 功能页的 SaaS 外壳”：Duix 上传、渲染和任务是唯一真实闭环，内容策划、作品、发布等页面缺乏共同业务对象和生产状态。生产级产品需要以下事实链：

Tenant / Workspace
  └─ IP / Brand
      └─ Campaign
          └─ Content Project
              ├─ Brief / Script / Storyboard versions
              ├─ Assets / Avatar / Voice / Consent
              ├─ Workflow Run / Step / Provider Job
              ├─ Deliverable versions / Review
              └─ Publish Record / Performance Signal

数字人是媒体生产中的能力节点，不是产品全部。任何页面和模型调用都应落到稳定业务对象；任何异步能力都应通过可恢复工作流；任何费用变化都应进入不可变账本；任何人脸和声音产物都应关联授权快照。

2. 三款竞品：真正值得学的部分

产品核心交互强项不应照搬对 ip-ai 的启发
营销获客智能体 7.0选择 IP → 生成文案 → 文案 → 配音 → 数字人 → 智能剪辑 → 标题封面 → 发布步骤完成条件、锁定、草稿恢复、从对标链接到改写单条视频线性向导不适合管理长期 IP、活动和团队借鉴“清晰步骤＋可编辑中间结果＋断点恢复”
亿万流量智能体工作台承接自然语言意图，再路由至工具；所有生成统一进入异步任务任务、积分、退款、重渲染、历史作品、管理后台和商业运营大量智能体/工具入口容易形成能力超市，用户仍需自己编排借鉴任务事实、账本、退款、客服与 Admin 控制面
轻语 IP固定流程区＋参数区＋状态区；自动跑完与手工精调并存IP 大脑、素材库、云/本地节点级切换、剪辑包装、多账号发布重型本地桌面依赖和无人值守发布会带来升级、风控和支持成本借鉴本地生产节点、素材复用、能力节点选择和强工作流

共同的生产门槛不是“有多少模型”，而是：完整链路、可编辑中间结果、资产复用、长任务恢复、费用可解释和发布可交付。竞品事实来自本地程序资源的只读分析与公开版本核验；未执行竞品页面中的安装命令或自动发布操作。

3. 推荐的用户端

1. 今日工作台

待做、待审核、失败、即将发布、活动进度和真实消耗；不是摆放虚构数据的仪表盘。

2. IP 大脑

身份、人群、Offer、证据库、语气、禁区、平台策略与版本，成为所有内容生成的上下文来源。

3. 营销活动

目标、主题、渠道、节奏、KPI、预算和内容项目列表，回答“为什么做这些内容”。

4. 内容工作室

支持想法、对标、产品资料和已有文案起步；管理选题池、脚本版本、平台变体与审核。

5. 数字人工作室

配音、形象、Duix、字幕、BGM、画中画、封面与审片；每一步可保存、重跑和替换。

6. 资产中心

素材、声音、形象、模板、脚本、作品和授权；区分可复用资产与单项目产物。

7. 任务中心

跨能力步骤、进度、成本、异常、重试、取消和人工介入；用户看到可解释状态。

8. 发布与复盘

账号、平台适配、发布记录、审核状态和可获得的效果数据，回流至活动与选题。

交互关键：保留“快速成片”作为首页捷径，让新用户像竞品向导一样快速完成第一条视频；后台自动建立最小 Campaign/Project，避免产生无归属的脚本、声音和成片。

5. New API 与数字人混合执行：编排层怎么设计

用户端 / 管理端
       ↓
Business API / Workflow
（业务对象、版本、状态、账本、授权、审计）
       ↓
Capability Gateway
（统一合同、策略、路由、回退、计量、幂等）
       ├──────────────→ New API → 通用云模型渠道
       ├──────────────→ Avatar/Media Job Router
       │                  ├─ Duix 本地/自托管 Worker 或云 API
       │                  └─ OpenTalking 自托管 Worker/远程推理
       └──────────────→ 视频包装 / 发布平台专用 Adapter

内部只暴露业务能力，不暴露供应商

text.generate、text.embed、image.generate、asr.transcribe、speech.synthesize、voice.clone、avatar.render、avatar.video_clone、avatar.session.realtime、video.compose、publish.content。

每次路由必须记录候选 Provider、排除原因、最终选择、执行位置、回退、策略版本、估算/实际成本和时延。这样切换 Duix、OpenTalking 或云供应商时，业务对象、前端流程和历史数据不会被供应商字段污染。

New API 的正确边界

适合：通用云模型渠道、模型映射、Key 管理、优先级/权重、失败重试、限流、日志与基础计费。不适合：替代你的 Tenant、Campaign、Project、数字人授权、长任务补偿、人工审片、发布记录和业务账本。官方资料显示它已覆盖渠道与多媒体/异步能力，但这并不等于它理解超级 IP 业务对象。参见 New API 官方仓库与功能指南。

本地数字人不是“填一个 localhost 地址”

浏览器和云端 SaaS 无法可靠、安全地直接调用客户机器的 localhost。Duix/OpenTalking Worker 应主动连接控制面，声明硬件、引擎版本和能力，使用短期任务凭证拉取获授权素材并回传进度与产物；节点掉线、版本不兼容、模型缺失和磁盘不足都要成为可观察状态。当前不把通用本地 LLM 平台列入产品范围。

6. Duix 与 OpenTalking 的产品定位

能力适合的用户任务当前决策
Duix Avatar / 云 API音频/文本驱动的视频合成；可本地、自托管或使用商业云路径Phase 1 主生产闭环，纳入 avatar.render
OpenTalking实时会话、音频/文本驱动视频创建和视频克隆；可插拔模型编排Phase 2 合同级 Spike，验证后作为第二引擎及 avatar.video_clone/avatar.session.realtime 扩展

两者都能参与数字人视频，但产品角色仍不同：Duix 已有现成适配基础和商业 API 路径；OpenTalking 是更宽的可插拔编排框架，最新版已覆盖视频创建/克隆，但需要验证具体后端、部署、成本、质量和 SLA。推荐统一合同、分期接入，而不是在业务代码里做两套流程。

7. 生产级 MVP 与路线图

MVP 验收不是“页面能点”。一个真实团队应能连续完成 10 个项目：创建工作空间 → 建 IP/授权资产 → 建最小活动/项目 → 生成和编辑脚本 → 配音 → Duix → 字幕/BGM/封面 → 审核 → 下载发布包 → 查看任务与实际消耗。
阶段目标核心交付通过标准
Phase 1
0–6 周		事实来源与 Duix 生产闭环Tenant/RBAC；IP/Campaign/Project/Asset/Consent；可恢复工作流；Duix 成片；账本；最小 Admin10 个真实项目成功率 ≥90%；单项目人工介入 <15 分钟
Phase 2
6–10 周		数字人双引擎编排Capability Catalog；Provider SDK；New API；OpenTalking Spike；媒体 Worker；路由、回退、计量、成本同一组 10 个任务切换引擎不改业务对象；状态/成本/产物完整
Phase 3
10–14 周		量产与发布闭环素材检索；包装模板；批量与审核；抖音官方发布；其他平台发布包；基础效果回流30 个发布任务完成 ≥90%；零账号风控事故

首版明确不做：30+ 独立智能体商店、把 OpenTalking 实时会话塞入主流程、通用本地 LLM 平台、全平台浏览器无人值守发布、OEM/复杂分销，以及“无限生成”“10 秒成片”等系统无法保证的承诺。

8. 发布与合规边界

  • 抖音优先走官方内容发布能力，并将授权范围、审核和失败原因写入 Publish Record。参见抖音开放平台。
  • 小红书官方分享开放平台偏 App 内调起分享/发布，不应把它等同于无人值守网页自动化。首版采用发布包或受控调起。参见小红书分享开放平台。
  • 面向公众提供生成式文本、图片、音频和视频服务，需要从底层支持内容安全、生成标识、投诉与处置。参见《生成式人工智能服务管理暂行办法》。
  • 人脸和声纹应按敏感个人信息风险设计授权、用途范围、到期、撤回、删除和审计。参见《个人信息保护法》。

9. 主要风险与反证

失败方式早期信号控制办法
再次做成页面 Demo页面增加，但真实项目仍不能贯通每项功能必须落业务对象、状态和验收指标
数字人混合执行复杂度失控Worker 失联、引擎版本漂移、素材传输失败、支持工单上涨只把数字人/媒体纳入 Worker；能力声明；严格兼容矩阵与回退链
Duix 产出不稳定口型、远景、输入素材导致高返工素材质量门、样本基准、任务可重跑；达不到 Kill 标准则缩小场景
任务与账本不一致重复扣费、失败未退款、对账差异幂等、不可变流水、预占/实扣/释放、补偿任务
发布引发账号风险授权失效、验证码、平台处罚官方 API 优先；首版保留人工确认；不承诺全自动
Campaign 模型对新手过重不知道从哪里开始、首条内容耗时变长默认快速成片入口；8–12 人原型对照后再定导航

反证也必须保留：New API 已支持多媒体和异步任务，自有双层网关会增加运维复杂度，必须用 Provider 替换实验证明收益；公开用户评价样本很少，不能据此推断付费意愿、留存或具体套餐价格。

10. 待确认与已确认决策

已确认：独立 SaaS；活动/项目主线＋快速成片；独立管理端边界；自有编排与 Capability Gateway；通用 AI 云优先、数字人视频允许混合执行；轻语 IP 全能力功能等价目标；Duix 主生产、OpenTalking 同期 Spike 后作为第二引擎。

  1. D-006：发布以官方能力优先；小红书/视频号首版采用导出包或调起发布。
