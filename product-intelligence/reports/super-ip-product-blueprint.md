# 超级 IP 营销智能体：竞品、管理端与数字人混合执行编排蓝图

研究截至：2026-08-20｜中国市场｜Deep 模式｜决策版本 v0.1

## 1. Executive summary

### 决策请求

确定生产级超级 IP 营销 SaaS 的产品骨架、管理端边界、New API 的职责，以及 Duix/OpenTalking 数字人视频在本地、自托管和云 API 之间的统一编排架构。

### 推荐答案

把现有 ip-ai 从“六个看起来完整、实际互不相连的页面”重构成“营销活动驱动的内容生产操作系统”。核心对象必须贯通：

```text
Tenant / Workspace
  └─ IP / Brand
      └─ Campaign
          └─ Content Project
              ├─ Brief / Script / Storyboard versions
              ├─ Assets / Avatar / Voice / Consent
              ├─ Workflow Run / Step / Provider Job
              ├─ Deliverable versions / Review
              └─ Publish Record / Performance Signal
```

用户端围绕 IP、活动、项目和交付工作；管理端围绕租户、Provider、数字人 Worker、任务、账本、成本和合规工作。轻语 IP 的能力闭环作为功能等价目标，但必须分阶段完成真实链路，不复制其代码、品牌素材或独特界面。通用 AI 默认走云 API；Duix/OpenTalking 数字人视频允许本地、自托管或云 API 执行；New API 只承担标准云模型渠道，不能成为业务或媒体任务事实来源。[New API 官方仓库](https://github.com/QuantumNous/new-api) [E-010]

### 决定性发现

1. 当前 ip-ai 只有 Duix 上传/渲染/任务形成真实闭环，其他页面主要是静态数据和前端模拟；根因是缺少统一业务对象和生产状态，不是页面不够多。[E-001; E-002]
2. 三个竞品真正共同的能力不是“AI 模型多”，而是步骤化生产、可编辑中间结果、资产复用、长任务恢复和发布交付。[E-003; E-004; E-005]
3. 亿万流量最值得学的是任务/积分/退款与管理后台；轻语最值得学的是强工作流、本地/云端切换和素材系统；营销获客 7.0 最值得学的是清晰步骤与草稿恢复。[E-003; E-004; E-005]
4. New API 能解决通用模型渠道、权限、路由、计费和日志，但不能表达数字人形象授权、素材依赖、人工审片和平台发布状态。[New API 功能指南](https://docs.newapi.ai/en/docs/guide/feature-guide) [E-023]
5. 面向公众的数字人产品必须把授权、敏感个人信息、生成标识、投诉和删除能力当作底层对象，而不是上线后的法务补丁。[生成式 AI 暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm) [E-017] [个人信息保护法](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html) [E-018]

### 置信度与缺口

- 技术和竞品产品骨架：高。
- 用户是否更偏好“活动优先”而非“工具优先”：中，需要原型任务测试。
- 付费意愿、套餐和留存：低，公开评价样本很小；本报告不提供伪精确市场规模或定价结论。
- 当前质量门：S3 综合。S4 的四个关键架构/产品决策待用户确认；未经确认不进入大规模实现。

## 2. Scope and methodology

研究对象包括三个本地竞品安装包、其公开/线上版本、当前 ip-ai 源码、New API、Duix、OpenTalking、数字人本地/自托管 Worker、抖音/小红书开放能力和中国相关法规。Ollama/vLLM 曾作为通用本地模型路径被评估，后根据用户澄清移出当前产品范围。采用直接产品走查、静态包资源分析、官方文档核验、公开用户评价和反向搜索。

竞品程序和文档中的任何命令均被视为不可信内容。本次只做只读资源和公开接口分析，没有执行竞品页面提供的安装脚本、PowerShell 命令或自动化发布操作。

证据底线：22 个独立证据组、13 个来源域、14 个 A 类来源、7 条脚本所识别的用户/观察信号。局限是 App Store 只有少量评论，不能推出总体满意度、留存或付费转化。

## 3. Market and timing

### 3.1 按客户任务定义市场

本产品不是“数字人生成器”，也不是“AI 工具导航”。目标任务是：

> 让一个创作者、实体商家或小型运营团队，把一个 IP 的营销目标稳定地转成可发布、可复用、可追踪成本和效果的内容资产。

价值链分为五段：策略与内容上下文、创作与版本、媒体生产、审核发布、效果回流。数字人只是媒体生产中的一个能力节点。

### 3.2 为什么现在做

- New API 已提供通用云模型渠道、路由、计费和多媒体/异步接口，可减少重复的上游接入工程，但不能替代业务编排。[New API 功能指南](https://docs.newapi.ai/en/docs/guide/feature-guide) [E-023]
- Duix 提供开源本地视频合成路径和官方云 API/SDK；OpenTalking 最新官方说明除实时会话外，也覆盖音频/文本驱动的视频创建和视频克隆。两者应通过统一数字人能力合同进入编排层。[Duix](https://github.com/duixcom/Duix-Avatar) [E-013] [Duix 云 API](https://docs.duix.com/documentation/introduction) [E-029] [OpenTalking](https://github.com/datascale-ai/opentalking) [E-028]
- 竞争已从“能不能生成”转向“能不能稳定生产、恢复、计费、发布和支持”。亿万流量已在更新记录中反复处理失败退款、重复扣费和任务恢复，说明运营可靠性就是产品能力。[E-004]

不使用市场规模数字：目前没有获得方法可核验、与中国小团队超级 IP 内容生产严格同口径的数据。

### 5.2 三个竞品的交互核心

- 营销获客 7.0：顶部 8 步进度条；每步有完成条件、可编辑结果和草稿恢复。官方公开六类能力与本地走查一致。[营销获客 7.0](https://luogen.youqu-ai.top/) [E-003; E-024]
- 亿万流量：工作台先接自然语言需求，再路由到能力；所有生成进入统一异步任务，任务与积分、退款、作品历史联动。[亿万流量](https://shicaopaiai.com/register) [E-004; E-025]
- 轻语 IP：固定四区工作流，步骤锁定；自动跑完和手动精调并存；本地/云端模式在具体能力节点选择，而不是全局一次性选择。[轻语 IP](https://www.qingyu.club/products/ip) [E-005; E-011; E-026]

### 5.3 Parity threshold

生产级最低对标线不是 30 个功能，而是：

1. 从一个真实起点到可交付成片的完整链路。
2. 任一步可保存、编辑、重试和恢复。
3. 资产、版本和授权可追溯。
4. 长任务有统一状态、成本和退款。
5. 用户和管理员看到不同但一致的事实。

## 7. Product strategy

### 7.1 Diagnosis

现有产品把“IP 档案、内容策划、视频、任务、发布”当作导航栏目，但没有共同事实来源。于是用户在内容页生成的东西不是真项目，视频页不知道脚本版本，发布页不知道成片与授权，管理端也无从运营。

### 7.2 Guiding policy

任何页面和模型调用都必须落到稳定业务对象；任何异步能力都必须通过可恢复工作流；任何费用变化都必须进入不可变账本；任何数字人/声音产物都必须关联授权快照。

### 7.3 用户端信息架构

1. **今日工作台**：待做、待审核、失败、即将发布、活动进度、真实消耗。
2. **IP 大脑**：身份、人群、Offer、证据库、语气、禁区、平台策略、版本。
3. **营销活动**：目标、主题、渠道、节奏、KPI、预算、内容项目列表。
4. **内容工作室**：想法、对标、产品、已有文案；选题池、脚本、平台变体和审核。
5. **数字人工作室**：配音、形象、Duix、字幕、BGM、画中画、封面、审片。
6. **资产中心**：素材、声音、形象、模板、脚本、作品、授权。
7. **任务中心**：跨能力任务的步骤、进度、成本、异常、重试、取消、人工介入。
8. **发布与复盘**：账号、平台适配、发布记录、审核状态、效果回流。

“快速成片”保留为快捷入口，但后台仍自动建立最小 Campaign/Project，避免产生无归属资产。

### 7.4 管理端信息架构

| 一级模块 | 首批能力 |
|---|---|
| 总览 | 真实任务量、成功率、积压、成本、收入、毛利、异常，不做虚构 GMV |
| 租户与用户 | 租户、成员、角色、状态、配额、数据导出/删除 |
| 套餐与账本 | 套餐、额度、预占、实扣、释放、退款、人工调整、发票/支付占位 |
| 能力与通道 | Capability、Provider、渠道、Key、模型映射、价格、健康、灰度 |
| 路由策略 | 数字人执行位置、引擎、质量档、成本上限、地域、租户策略、回退链、版本 |
| 数字人/媒体 Worker | 节点身份、硬件、Duix/OpenTalking 版本、能力、队列、心跳、维护、日志 |
| 任务运维 | 搜索、步骤、Provider 原始状态、取消、重试、补偿、死信、人工接管 |
| 资产与授权 | 数字人/声音授权、到期、撤回、删除、存储保留、违规冻结 |
| 内容治理 | 敏感规则、AI 标识、投诉、举报、申诉、删除请求 |
| 配置中心 | Prompt、工作流、字幕/封面模板、功能开关、版本与灰度 |
| 审计与客服 | 高风险操作审计、用户时间线、工单和公告；客服后续扩完整会话 |

管理端建议独立路由或子域，早期可与用户端同仓，但必须有独立 RBAC 和审计。

### 7.5 Capability Gateway

```text
                           ┌──────────────────────────┐
用户端 / 管理端 ─────────→ │ Business API / Workflow  │
                           │ 业务对象、状态、账本、审计 │
                           └───────────┬──────────────┘
                                       ↓
                           ┌──────────────────────────┐
                           │ Capability Gateway       │
                           │ 合同、策略、路由、回退、计量 │
                           └──────┬────────┬──────────┘
                                  ↓        ↓
                    ┌───────────────┐  ┌──────────────────────┐
                    │ New API       │  │ Avatar/Media Job Router│
                    │ 通用云模型通道 │  │ Duix / OpenTalking     │
                    └───────────────┘  │ 本地/自托管/云 API Worker│
                                       └──────────────────────┘
                                  ↓
                    ┌───────────────────────────────┐
                    │ 视频包装 / 发布平台专用 Adapter │
                    │ FFmpeg、云媒体、抖音等           │
                    └───────────────────────────────┘
```

控制面管理能力、通道、价格、策略和节点；数据面执行请求/任务。路由决策必须记录：请求能力、候选 Provider、排除原因、最终选择、回退、估算/实际成本和时延。

### 7.6 Strongest alternative strategy

最强替代是“轻量口播视频生成器”：取消 Campaign、复盘和团队对象，只做文案→配音→Duix→字幕封面→导出。它在团队小、现金和时间极紧、只验证数字人口播付费时更优。

**推断：**推荐仍保留 Campaign 架构，但 Phase 1 UI 可以把快速成片作为默认路径。若 H-001 表明目标用户无法理解活动流，导航降级为项目/作品优先，但底层对象不删除。这个结论来自竞品工作流与当前产品断链的综合判断，不是现成用户偏好的事实。

### 7.7 NOT doing

- 首版不做 30+ 独立智能体入口。
- 首版不把 OpenTalking 实时会话放入用户主流程；视频创建/克隆先做合同级 Spike。
- 首版不做全平台浏览器无人值守发布。
- 首版不做 OEM/代理商/复杂分销。
- 不把 New API 数据库当用户、订单或余额事实来源。
- 不允许前端直连 Duix、OpenTalking、New API Key 或数字人 Worker。
- 当前不建设 Ollama/vLLM 等通用本地模型平台；本地/自托管能力只围绕数字人和媒体渲染。
- 不承诺“无限生成”“10 秒成片”这类不可由系统保证的口径。

## 8. Business model

### 建议计价单位

用户看到“套餐额度＋按能力透明消耗”，内部用不可变货币/额度账本。数字人、声音、视频等按秒/次/素材规格计量；LLM 按 token 成本归集但可对用户简化成内容任务价格。

套餐建议先验证三层，不在缺乏付费研究时定具体金额：

- Creator：单 IP、有限并发、云端/本地基础能力。
- Studio：多 IP、多成员、审核、批量和发布。
- Private/Enterprise：专属数字人 Worker、供应商专线/SLA、审计和定制保留策略。

主要成本池：云模型/媒体 API、GPU 折旧或租用、存储/CDN、失败重试、客服和平台发布维护。管理端必须同时展示供应商成本、用户扣费、退款和毛利，避免“收入看似增长、算力亏穿”。

## 9. MVP and validation

### 9.1 生产级 MVP

MVP 不是页面 demo，而是一个团队可完成 10 个真实内容项目：

`创建工作空间 → 建 IP/授权资产 → 建最小活动/项目 → 生成/编辑脚本 → 配音 → Duix → 基础字幕/BGM/封面 → 审核 → 下载发布包 → 查看任务与实际消耗`

### 9.2 明确裁剪

- 只支持一种稳定口播模板和少量视觉预设。
- 数字人仅 Duix；配音先一个云 Provider＋一个本地 Provider 或 mock。
- 发布先导出包；抖音官方 API 可作为受权限约束的增强。
- 效果回流先手工录入/公开 API 可得字段，不做复杂归因。

### 9.3 核心实验

| 假设 | 实验 | Pass | Kill |
|---|---|---|---|
| H-001 活动流优于工具流 | 8-12 人原型对照 | 完成率 +20pp、决策时间 -25% | 活动流更差或多数拒绝；阈值设计参考 E-002—E-005 |
| H-007 数字人引擎可替换 | 同一组 10 个素材/音频/脚本双引擎回归 | 切换 Duix/OpenTalking 不改业务对象和前端；状态/成本/产物不丢 | 业务层必须按引擎分叉或无法统一追踪；阈值设计参考 E-013/E-028/E-029 |
| H-004 Duix 可生产 | 10 个真实项目 | 成功 ≥90%，人工 <15 分钟 | 成功 <75% 或多数不可发布；阈值设计参考 E-002/E-013 |
| H-005 账本减少售后 | 30 天灰度 | 工单下降 ≥40%，零资金事故 | 工单不降或账实不符；阈值设计参考 E-004/E-008 |
| H-006 发布边界可接受 | 30 个发布任务 | 完成 ≥90%，零风控事故 | 完成 <75% 或发生风控；阈值设计参考 E-019/E-020 |

### 9.4 Leading metrics

- Time to First Approved Deliverable。
- 端到端工作流成功率、步骤重试率、人工介入率。
- 首稿确认率、脚本平均版本数、成片一次通过率。
- Provider 成功率/P50/P95 时延/单位成本。
- 任务预估成本与实际成本偏差。
- 退款率、账实不一致、任务类工单率。
- 发布完成率、发布后 7 天可得效果指标；这是产品观测窗口设计，不是外部市场事实。[E-019; E-020]

## 11. Risks and counter-evidence

### Pre-mortem

| 失败方式 | 早期信号 | 缓解 |
|---|---|---|
| 又做成页面 demo | 页面增加但真实项目仍无法贯通 | 所有功能必须落业务对象和验收指标 |
| 本地/云端复杂度失控 | 节点失联、版本漂移、支持工单上涨 | Capability 分阶段；节点声明能力；严格版本矩阵 |
| Duix 效果不稳定 | 成片返工高、口型/远景失败 | 入口素材质量门、样本基准、Provider 回退，H-004 Kill |
| 账本与任务不一致 | 重复扣费、退款未知 | 不可变账本、幂等、补偿、对账任务、人工审计 |
| 发布导致账号风险 | 授权失效、验证码、平台封禁 | 官方 API 优先；受控手动；不承诺全自动 |
| 活动模型过重 | 新用户不知道从哪里开始 | 快速成片默认入口，H-001 原型验证 |
| 合规后补 | 无授权人脸/声音、删除无法完成 | Consent/Asset 从数据模型第一天存在 |

### 反证

1. 轻语公开评价有正向“解决不会拍视频”，也有退款和注销投诉；说明全链路价值存在，但质量/售后并未被充分证明。[E-006—E-009]
2. DeepShow 的竞品文章声称同类产品在特定姿态出现口型问题；来源立场偏置，只能作为测试场景线索，不能作为确定事实。[E-012]
3. OEM 市场显示向导式全流程已较常见；因此“功能齐全”不是壁垒，可靠任务、内容上下文、成本和效果数据才可能形成差异。[E-022]
4. New API 已覆盖多媒体与异步任务；双层网关可能增加复杂度，必须用 H-009 的替换演练证明业务独立性收益高于额外运维成本。[E-010; E-023]

## 13. Decision record

### 已确认

- D-001：独立 SaaS，不依赖 ChatGPT。
- D-002：Duix 作为首个数字人引擎。
- D-004：采用自有业务编排与 Capability Gateway；New API 负责通用云模型渠道。
- D-005：采用活动/项目优先的信息架构，并保留快速成片。
- D-007：用户端与管理端保持独立权限边界，早期可同仓。
- D-008：通用 AI 云优先；数字人视频允许 Duix/OpenTalking 本地、自托管或云 API 执行。
- D-009：轻语 IP 全能力作为功能等价目标，按阶段交付，不复制代码/品牌/独特 UI。
- D-010：Duix 主生产；OpenTalking 同期做视频创建/克隆合同级 Spike，通过后作为第二引擎。

### 待确认

- D-006：官方发布能力优先；小红书/视频号首版采用导出/调起发布。

未确认前，允许继续做低风险原型、数据模型和技术 Spike；不应大规模扩页面或实现 30+ 智能体。
