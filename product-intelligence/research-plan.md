# Research Plan

| ID | Lane | Research question | Preferred evidence | Disconfirming query | Decision impact | Stop condition | Status |
|---|---|---|---|---|---|---|---|
| RQ-001 | competitors | 三个本地竞品分别承诺什么、导航暴露哪些对象、用户如何从输入到可发布结果？ | 实际产品、Electron 资源、官方页面 | 失败态、空状态、退款、导出、历史版本是否缺失 | high | 三款均形成模块图与端到端流程 | active |
| RQ-002 | users | 目标用户真正购买的是“内容生成”还是“获客运营结果”，单 IP 与多 IP 团队的工作流差异是什么？ | 用户直接反馈、产品评论、社区问题、人工工作流 | 不续费、太复杂、生成质量不足、仍需人工返工 | high | 至少 5 个独立用户信号或记录证据不足 | active |
| RQ-003 | technology | New API 哪些机制适合借鉴，哪些不能替代业务编排、资产与任务系统？ | 官方文档、官方仓库、配置与架构说明 | 渠道兼容性、故障隔离、计费准确性、供应商锁定 | high | 模型接入、路由、令牌、额度、日志和边界均核验 | active |
| RQ-004 | operations | 生产级管理端首版需要哪些看板、配置、审计和处置动作？ | 竞品管理/会员/任务状态、New API 管理面、当前后端风险 | 只有 CRUD 没有成本、失败、投诉与权限闭环 | high | 输出 P0/P1/P2 管理端范围与权限边界 | active |
| RQ-005 | economics | 多供应商与本地 GPU 混合时，怎样控制每次作品的成本、失败扣费和毛利？ | 供应商计费文档、任务重试行为、New API 额度/日志机制 | “无限量”、失败仍计费、成本不可归因 | high | 建立可计算的账本对象和路由约束 | active |
| RQ-006 | strategy | 产品应以单点工具集合、线性生产工作流还是多 IP 运营 OS 为主骨架？ | 竞品系统比较、用户任务、切换成本 | 大而全导致首个价值慢；运营 OS 对单人过重 | high | 推荐一个主骨架、一个备选并写明反转条件 | active |
